# Деплой QairuCowork: сайт + телеграм-бот

Пошаговый план с нуля до работающего бота. Считаем, что не сделано ещё ничего:
нет ни репозитория, ни базы, ни бота.

**Времени нужно:** ~40 минут, из них половина — ожидание сборки.
**Денег:** 0 ₸. Vercel Hobby и Supabase Free покрывают всё, что здесь описано.

---

## Главное, что нужно понять до начала

**Бот — это не отдельная программа.** Не нужно арендовать сервер, ставить туда
Python и держать процесс включённым. Бот живёт внутри сайта как один обычный
адрес: `/api/telegram/webhook`. Телеграм сам стучится в этот адрес, когда кто-то
пишет боту.

Отсюда весь план:

```
                       ┌──────────────────────────┐
   пользователь ──────►│  Vercel (один проект)    │
   в браузере          │                          │
                       │   /g/abc123   — сайт     │
   пользователь ──────►│   /api/telegram/webhook  │
   в телеграме         │               — бот      │
                       └────────────┬─────────────┘
                                    │
                            ┌───────▼────────┐
                            │   Supabase     │
                            │  (PostgreSQL)  │
                            └────────────────┘
```

**Один деплой = и сайт, и бот сразу.** Завести нужно три вещи: репозиторий на
GitHub, базу в Supabase, проект в Vercel. Плюс самого бота у BotFather.

## Шаг 1. Положить код на GitHub

Vercel собирает проект из репозитория. Сейчас папка репозиторием не является,
поэтому начинаем отсюда.

**1.1. Создать репозиторий локально**

```powershell
cd C:\Users\Амир\Desktop\qairu-cowork\qairu-cowork\qairu-cowork
git init
git add .
git commit -m "QairuCowork: сайт и телеграм-бот на Next.js"
```

`.gitignore` уже настроен: `node_modules`, `.next` и `.env.local` внутрь не попадут.
Проверить, что секретов в коммите нет:

```powershell
git ls-files | Select-String "\.env"
```

Вывод должен быть пустым. Файл `.env.example` без значений — не в счёт, он полезен.

**1.2. Создать пустой репозиторий на GitHub**

[github.com/new](https://github.com/new) → имя `qairu-cowork` → **Private** →
**не** добавлять README, .gitignore и лицензию (иначе будет конфликт при пуше) →
**Create repository**.

**1.3. Отправить код**

Команды покажет сам GitHub на странице нового репозитория; выглядят они так:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/qairu-cowork.git
git branch -M main
git push -u origin main
```

✅ **Готово, когда:** код виден на github.com, а файла `.env.local` там нет.

## Шаг 2. База данных в Supabase

**2.1. Создать проект**

[supabase.com](https://supabase.com) → **New project**.

- Name: `qairu-cowork`
- Database Password: сгенерировать и **сразу сохранить** — второй раз его не покажут.
- Region: ближайший к пользователям (`eu-central-1` для Казахстана — разумный выбор).

Создание занимает 1–2 минуты.

**2.2. Скопировать строку подключения — именно пулер**

**Project Settings → Database → Connection pooling → Transaction**, порт **6543**.

Строка выглядит так:

```
postgresql://postgres.abcdefgh:ПАРОЛЬ@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
```

Подставьте в неё пароль из шага 2.1 вместо слова `ПАРОЛЬ`.

> **Почему пулер, а не прямое подключение (порт 5432).** На Vercel каждый запрос
> обслуживает отдельная функция, и каждая открыла бы своё соединение с базой.
> Лимит соединений кончится раньше, чем трафик. Пулер держит соединения за них.
>
> Если в пароле есть символы `@ : / ? # &` — их надо закодировать (`@` → `%40`),
> иначе строка подключения разберётся неправильно.

**2.3. Создать таблицы**

**SQL Editor → New query** → вставить целиком содержимое файла
[`drizzle/0000_init.sql`](drizzle/0000_init.sql) из проекта → **Run**.
Затем так же, отдельными запросами, — [`drizzle/0001_admin_login.sql`](drizzle/0001_admin_login.sql)
[`drizzle/0002_avatars.sql`](drizzle/0002_avatars.sql) и [`drizzle/0003_real_name.sql`](drizzle/0003_real_name.sql).

Миграции выполняются **по порядку номеров** и **каждая один раз**. Если база уже
работает на прошлой версии (`0000` выполнен давно), при обновлении нужно выполнить
только `0001_admin_login.sql`: он добавит роли участников, вход по паролю и
уведомления на сайте, а создателем каждой старой группы с сайта сделает её
первого участника. `0002_avatars.sql` добавляет таблицу фото профиля, `0003_real_name.sql` — колонку настоящего имени.

✅ **Готово, когда:** в **Table Editor** появились таблицы `users`, `chats`,
`memberships`, `busy_slots`, `meetings`, `credentials`, `notices`, `avatars` и остальные.

## Шаг 3. Проект в Vercel

**3.1. Импортировать репозиторий**

[vercel.com](https://vercel.com) → войти через GitHub → **Add New → Project** →
найти `qairu-cowork` → **Import**.

Настройки сборки Vercel определит сам (Next.js). Менять там ничего не нужно.

**3.2. Добавить переменную окружения**

В разделе **Environment Variables** на той же странице:

| Name | Value |
|---|---|
| `DATABASE_URL` | строка подключения из шага 2.2 |

Область — все три окружения (Production, Preview, Development).

**3.3. Нажать Deploy**

Сборка идёт 2–3 минуты. Vercel выдаст адрес вида
`https://qairu-cowork.vercel.app`. **Запишите его** — он понадобится дальше.

✅ **Проверка:**

- `https://ваш-адрес.vercel.app/api/healthz` → `{"ok":true}` — сайт жив;
- главная страница открывается, кнопка создания группы работает и выдаёт ссылку
  вида `/g/abc123` — значит, база подключена правильно.

Если группа не создаётся — почти всегда дело в `DATABASE_URL`. Логи:
**Vercel → проект → Deployments → последний → Runtime Logs**.

На этом **сайт уже полностью работает**: группы, расписания, тепловая карта,
встречи. Телеграм для этого не нужен.

## Шаг 4. Создать бота у BotFather

**4.1. Сам бот**

В Телеграме открыть [@BotFather](https://t.me/BotFather):

1. `/newbot`
2. Имя (что видят люди): `Qairu Cowork`
3. Username (обязан заканчиваться на `bot`): например `qairu_cowork_bot`
4. BotFather пришлёт **токен** вида `1234567890:AAF...`. Это пароль от бота:
   хранить как пароль, в переписку и в код не класть.

**4.2. Разрешить добавлять бота в группы**

Обязательно, иначе главный сценарий не заработает:

```
/setjoingroups → выбрать своего бота → Enable
```

**4.3. Описание и картинка (по желанию)**

```
/setdescription — Находит общие свободные окна у группы
/setabouttext   — Расписание группы и общие окна
/setuserpic     — аватар бота
```

✅ **Готово, когда:** токен на руках и добавление в группы разрешено.

## Шаг 5. Подключить бота к сайту

Здесь **важен порядок**: вебхук регистрируется во время сборки, поэтому токен
должен появиться в Vercel *до* неё.

**5.1. Добавить токен**

**Vercel → проект → Settings → Environment Variables → Add New**:

| Name | Value | Окружения |
|---|---|---|
| `BOT_TOKEN` | токен из шага 4.1 | Production (и Preview, если заведёте отдельного тестового бота) |

**5.2. Пересобрать проект**

**Deployments → последний деплой → «…» → Redeploy.**

Во время сборки скрипт `scripts/set-webhook.mjs` сам:

- пропишет Телеграму адрес `https://ваш-адрес.vercel.app/api/telegram/webhook`;
- выведет секрет заголовка из токена (отдельная переменная не нужна);
- загрузит меню команд — отдельно для личных чатов и для групп.

В логе сборки появится строка:

```
[qairu:webhook] вебхук зарегистрирован: https://…/api/telegram/webhook (бот @qairu_cowork_bot)
```

> **Вебхук ставится только на продакшен-сборке.** Превью-деплои получают новый
> адрес на каждый коммит; если бы они перехватывали вебхук, рабочий бот
> отваливался бы после каждого пуша в ветку.

✅ **Проверка бота:**

1. Открыть бота в Телеграме → `/start` → приходит приветствие;
2. `/schedule` → прислать текстом `пн 10:00-12:00` → расписание сохранилось;
3. Создать тестовую группу, добавить туда бота, выдать ему права администратора,
   отправить `/setup` → бот подключает чат и присылает ссылку на сайт;
4. `/availability` в группе → бот показывает общие свободные окна.

## Шаг 6. Напоминания о встречах (cron)

Уже настроено в [`vercel.json`](vercel.json): Vercel раз в сутки в 06:00 UTC
дёргает `/api/cron/reminders`, и бот рассылает напоминания о встречах ближайшего дня.
Переменную `CRON_SECRET` Vercel подставляет сам — заводить её руками не нужно.

Если раза в сутки достаточно — делать ничего не надо. **На тарифе Hobby чаще нельзя.**

Если нужна точность «за 30 минут до встречи», два пути:

- **Vercel Pro** — поменять расписание в `vercel.json` на `*/5 * * * *`;
- **бесплатно** — оставить как есть и повесить внешний пингер
  ([cron-job.org](https://cron-job.org), GitHub Actions) каждые 5 минут на адрес:

  ```
  https://ваш-адрес.vercel.app/api/cron/reminders?secret=ЗНАЧЕНИЕ_CRON_SECRET
  ```

  Тогда `CRON_SECRET` нужно задать в Vercel явно — своей случайной строкой.

## Шаг 7. По желанию: свой домен и вход одним касанием

**Свой домен.** **Vercel → Settings → Domains** → добавить домен → прописать
DNS-записи, которые покажет Vercel. После этого добавить переменную
`NEXT_PUBLIC_SITE_URL=https://ваш-домен` и **сделать Redeploy** — иначе вебхук и
ссылки в сообщениях бота останутся на старом адресе `*.vercel.app`.

**Кнопка-меню (Mini App).** Если открыть сайт прямо из Телеграма, человек
опознаётся автоматически: расписание из бота и с сайта оказывается одним и тем же,
без входа по ссылке. У BotFather:

```
/setmenubutton → выбрать бота → указать https://ваш-адрес.vercel.app
```

Без этого всё работает тоже — просто на сайт заходят по ссылке-приглашению.

## Переменные окружения: полный список

| Переменная | Обязательна | Зачем |
|---|---|---|
| `DATABASE_URL` | **да** | подключение к Supabase, обязательно пулер (порт 6543) |
| `BOT_TOKEN` | для бота | токен от BotFather; без него сайт работает, бота нет |
| `NEXT_PUBLIC_SITE_URL` | нет | только если свой домен или локальный туннель |
| `TELEGRAM_WEBHOOK_SECRET` | нет | по умолчанию выводится из `BOT_TOKEN` |
| `CRON_SECRET` | нет | Vercel подставляет сам; задать, если нужен внешний пингер |
| `DEFAULT_TZ` | нет | по умолчанию `Asia/Almaty` |
| `DEFAULT_LANG` | нет | по умолчанию `ru` |

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| Сайт открылся, но группа не создаётся | Неверный `DATABASE_URL` или не выполнен `0000_init.sql`. Смотреть Runtime Logs в Vercel |
| Страница группы падает с ошибкой про `role`, `created_by`, `credentials` или `notices` | Не выполнена миграция `0001_admin_login.sql` |
| Фото профиля не сохраняется («Не удалось загрузить фото») | Не выполнена миграция `0002_avatars.sql` |
| Сайт падает с ошибкой про `real_name` | Не выполнена миграция `0003_real_name.sql` |
| `too many connections` в логах | Взято прямое подключение (5432) вместо пулера (6543). Заменить строку и сделать Redeploy |
| Бот молчит на `/start` | Вебхук не зарегистрирован: `BOT_TOKEN` добавлен, но Redeploy не сделан. Проверить: `https://api.telegram.org/botТОКЕН/getWebhookInfo` — там должен быть ваш адрес и пустой `last_error_message` |
| Бота нельзя добавить в группу | Не сделан `/setjoingroups → Enable` у BotFather |
| Бот в группе не отвечает на команды | Не отправлен `/setup`, либо у бота нет прав администратора |
| Адрес сайта поменялся, бот отвечает на старом | Зарегистрировать вебхук без пересборки: `https://новый-адрес/api/telegram/setup?secret=СЕКРЕТ`. Секрет — первые 48 hex-символов от `sha256("qairu-webhook:" + BOT_TOKEN)`; его печатает `npm run bot:webhook` |
| Напоминания не приходят | Cron на Hobby идёт раз в сутки. См. шаг 6 |

**Где смотреть логи:** Vercel → проект → **Deployments** → нужный деплой →
**Runtime Logs** (ошибки бота и сайта) и **Build Logs** (ошибки сборки и вебхука).

## Как обновлять дальше

```powershell
git add .
git commit -m "что изменилось"
git push
```

Vercel соберёт и выкатит сам, вебхук перерегистрируется в той же сборке.
Правило одно: **перед пушем прогнать `npm test` и `npm run build`** — упавшая
сборка не выкатится, но и рабочая версия останется старой.

**Изменения в схеме базы:** `npm run db:generate` создаёт новый SQL-файл в
`drizzle/`; его нужно выполнить в Supabase SQL Editor вручную — Vercel миграции
сам не накатывает.
